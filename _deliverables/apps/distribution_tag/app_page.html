distribution_tag C++17 DISTRIBUTED

Master / Worker content-tagging pipeline · uses all six DISTRIBUTED primitives
Executables

🖥️ distribution_tag_master

Coordinator node. Enqueues tagging jobs, spawns worker threads, monitors health via the ServiceRegistry, and protects against faults with a shared CircuitBreaker.
./distribution_tag_master [num_workers] # default: 4 workers, 20 jobs ./distribution_tag_master ./distribution_tag_master 8

⚙️ distribution_tag_worker

Standalone worker node. Seeds its own local job queue and demonstrates the full worker lifecycle: register → subscribe → process → heartbeat → deregister.
./distribution_tag_worker [id [jobs]] # default: worker-standalone, 10 jobs ./distribution_tag_worker ./distribution_tag_worker worker-A 20

DISTRIBUTED library primitives

📬 TaskQueue<Job>

Unbounded thread-safe queue. Master enqueues all jobs upfront; workers consume via dequeue_for(400ms) — returns nullopt when drained, signalling clean shutdown.

📡 MessageBus

Each enqueued job triggers a publish("jobs", id). Workers subscribe before entering the consume loop, so they wake immediately rather than polling.

🗂️ ServiceRegistry

Workers register_service on start and call heartbeat each iteration. The master's monitor thread calls expire_stale(5 s) to detect crashed workers and mark them unhealthy.

🔒 DistributedLock

Before committing a result to the shared TaskQueue<JobResult> each worker acquires the write lock with a 500 ms timeout, simulating mutual exclusion over a shared result store.

⚡ CircuitBreaker

Wraps each classification call. After 4 consecutive failures the circuit opens and subsequent calls fast-fail. After 300 ms the circuit probes in HalfOpen; 2 successes restore normal operation.

📋 RaftNode available

Leader election and log replication from consensus/. Not wired into this demo — relevant when the master role itself needs to be replicated across multiple coordinator processes for high availability.
